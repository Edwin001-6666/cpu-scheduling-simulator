API:
  parse_processes_csv(csv_source: str | IO[str]) -> CsvParseResult

  CsvParseResult:
    .is_valid      (bool)
    .processes     (list[Process])   — populated when is_valid is True
    .errors        (list[CsvParseError]) — populated when is_valid is False
    .extra_columns (list[str])       — extra header columns found (info only)

  CsvParseError:
    .field   (str)       — column name or "csv" for structural errors
    .message (str)       — human-readable, suitable for direct UI display
    .row     (int|None)  — 1-based data row number; None for structural errors

Supported CSV format:
  Canonical header (order-independent, case-sensitive):
    PID,Arrival Time,Burst Time,Priority
  Extra columns: silently ignored; surfaced in CsvParseResult.extra_columns
  Blank lines: silently skipped
  Quoted fields: supported (RFC 4180 via stdlib csv module)
  Windows CRLF: supported

Separation of concerns:
  - Parsing converts CSV text → Process objects. It does NOT call
    validate_processes() internally.
  - Semantic validation (negative arrival, zero burst, duplicate PIDs, etc.)
    is deliberately left to B1 validate_processes().
  - The caller controls when to run each step:
      parsed   = parse_processes_csv(source)
      if parsed.is_valid:
          valid = validate_processes(parsed.processes)
          if valid:
              result   = algo.schedule(parsed.processes)
              enriched = compute_metrics(result, parsed.processes)
