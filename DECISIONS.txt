CPU Scheduling Lab — Project-wide Decision Log

- Priority convention: LOWER numeric value means HIGHER priority.
- SJF is initially non-preemptive.
- Priority Scheduling is initially non-preemptive.
- Round Robin will be preemptive.
- Round Robin time quantum must be positive.
- PID must be unique.
- Arrival Time must be >= 0.
- Burst Time must be > 0.
- CPU idle periods must be explicitly representable.
- Scheduling logic must remain independent of the UI.
- Scheduling-engine interface: all algorithms subclass SchedulingAlgorithm (algorithms/base.py), an abstract base class with two abstract members — a `name` property (str) and a `schedule(processes: Sequence[Process]) -> SimulationResult` method.
- Algorithm-specific configuration (e.g. Round Robin's time quantum) is passed to each subclass's __init__. The base class takes no configuration. This avoids forcing FCFS/SJF/Priority to accept a time_quantum they do not use. Round Robin's __init__ will accept `time_quantum: int`; other algorithms' __init__ will take no extra arguments.
- The interface imposes no assumption about preemptive vs non-preemptive behavior, so future preemptive algorithms can be added without redesigning the architecture.
- FCFS tie-breaking: when multiple processes share the same arrival time, they are ordered by PID (lexicographic). This guarantees deterministic output regardless of input order.
- FCFS sets response_time equal to waiting_time (non-preemptive: first dispatch is after the full wait).
- SJF is non-preemptive: once a process starts executing it runs to completion. A shorter job arriving mid-execution does not preempt the running process.
- SJF tie-breaking: when multiple ready processes have the same burst time, select by earliest arrival_time, then by PID (lexicographic). Effective sort key: burst_time → arrival_time → pid.
- Priority Scheduling confirmed: lower numeric priority value = higher scheduling priority (priority 1 beats priority 3). This applies to the PriorityScheduler class in algorithms/priority.py.
- Priority Scheduling is non-preemptive: once a process starts executing it runs to completion. A higher-priority process arriving mid-execution does not preempt the running process.
- Priority Scheduling tie-breaking: when multiple ready processes have the same priority value, select by earliest arrival_time, then by PID (lexicographic). Effective sort key: priority → arrival_time → pid.
- Round Robin is preemptive. Each process runs for at most time_quantum time units before being preempted and placed at the back of the ready queue.
- Round Robin time_quantum must be a positive integer. The RoundRobin __init__ defensively rejects zero, negative, and non-integer values with a ValueError.
- Round Robin ready-queue policy: processes are initially enqueued in (arrival_time, pid) order for determinism. The queue is FIFO.
- Round Robin arrival-during-quantum: when a quantum expires and new processes have arrived during that slice, the newly arriving processes are enqueued FIRST, then the preempted process is re-queued at the back. This is the standard textbook convention.
- Round Robin arrival at quantum boundary: a process arriving at exactly the same time a quantum expires is considered ready at that time and enters the queue before the preempted process.
- Validation layer lives in core/validation.py. It is separate from all scheduling algorithms and from the Streamlit UI. Algorithms may assume their input has been validated; validation is not repeated inside algorithms.
- Validation returns a ValidationResult (is_valid: bool, errors: list[ValidationError]) rather than raising exceptions. This allows the UI to collect and display all errors at once rather than stopping at the first failure.
- ValidationError carries three fields: field (str), message (str), process_id (str|None). The UI may display message directly as a user-facing string.
- Validation never silently corrects invalid input (e.g. negative arrival time is reported, not clamped to 0). The user must fix inputs explicitly.
- PID validation: PID must be a non-empty string, must not equal IDLE_PROCESS_ID ("IDLE"), and must be unique within the process list.
- Priority validation: any integer is valid. No upper/lower bound is imposed beyond being a Python int. This is consistent with the model and the lower=higher-priority convention.
- Round Robin quantum validation: quantum must be a positive plain int. bool, float, str, and None are all rejected explicitly.
- validate_processes() accepts unsorted process lists; it does not require arrival-time ordering.
- core/__init__.py exports ValidationError, ValidationResult, validate_processes, validate_round_robin_quantum so callers can import from core directly.
- Metrics layer lives in core/metrics.py. It post-processes a SimulationResult and returns an enriched copy. It does not replicate scheduling logic.
- compute_metrics(result, processes) is the single public entry point. Laptop C calls it after algo.schedule().
- Response time formula: response_time = first_dispatch_start_time - arrival_time. "First dispatch" is the start_time of the first non-idle ExecutionSegment with process_id == pid (scanning segments in order). This correctly handles Round Robin (preemptive) where a process may appear in multiple segments.
- CPU utilization is expressed as a percentage (0.0–100.0): (busy_time / total_time) * 100.0. busy_time = sum of non-idle segment durations; total_time = last segment end_time - first segment start_time. Idle periods (IDLE_PROCESS_ID segments) are excluded from busy_time automatically.
- Throughput = n_processes / total_time (processes per unit of simulated time). total_time is the same wall-clock span as used for cpu_utilization.
- compute_metrics does not mutate its inputs. SimulationResult is a frozen dataclass; a new instance is constructed and returned.
- core/__init__.py exports compute_metrics so callers can use `from core import compute_metrics`.
- CSV import layer lives in core/csv_import.py. It converts CSV text → Process objects. It does NOT call validate_processes() internally; parsing and semantic validation are separate concerns.
- Canonical CSV column header (case-sensitive, order-independent): PID,Arrival Time,Burst Time,Priority.
- Extra CSV columns beyond the four required ones are silently ignored. Their names are surfaced in CsvParseResult.extra_columns so the UI can optionally show a warning. This allows richer CSV files (e.g. with Notes or Department columns) to be parsed without error.
- Blank lines in the CSV body are silently skipped.
- Decimal numeric strings (e.g. "3.5") are a parse error; only whole-number strings are accepted for arrival_time, burst_time, and priority.
- Negative integer values (e.g. "-1") are parsed successfully and passed through to validate_processes(), which produces the appropriate user-facing message. This keeps semantic checking in one place (B1).
- parse_processes_csv() accepts both str (CSV text) and file-like text objects (io.StringIO, open(), Streamlit UploadedFile). This avoids filesystem coupling.
- CsvParseResult.errors uses CsvParseError (not ValidationError) so that parse errors and validation errors remain distinct types for the UI to handle separately.
- CsvParseError.row is a 1-based data row index (None for structural errors), giving the UI precise location information for highlighting bad rows.
